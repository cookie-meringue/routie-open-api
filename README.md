# 개요

## 루티란?

자신의 동선이 실현 가능한 동선인지 확인할 수 있는 서비스.

동선 내 장소 간 거리와 이동 소요 시간 계산을 통해 동선이 실현 가능한지 판단해 줄 수 있다.

장소 간 이동 거리, 시간 계산 방식엔 자동차 이동 방식과 대중교통 이동 방식이 있다.

## 요구사항 정의와 의미 분석

### 1. 어떤 API 를 제공할 것인가?

#### 💡동선 검증 API

장소 목록을 통해 동선이 실현 가능한 동선인지 확인할 수 있는 API 입니다.

루티의 동선 검증 기능은 다른 개발자가 자신의 서비스에 통합할 수 있는 유용한 도구입니다. 이 API를 활용해 여행사, 여행 블로그, 지도 애플리케이션 등 다양한 종류의 서비스를 만들 수 있습니다.

### 2. 클라이언트란 무엇이며, 루티 Open API 의 클라이언트는 누가 될 것인가?

💡**클라이언트란?**

클라이언트는 우리 API를 호출하고 데이터를 전달받는 모든 주체입니다.

> ex 1) (프론트엔드) → (백엔드) 통신에선 프론트엔드 개발자가 클라이언트입니다.
>
> ex 2) (외부 서버) → (루티 서버) 통신에선 외부 서버 개발자가 클라이언트입니다.

💡**루티 Open API 의 클라이언트는 누구인가?**

**외부 서비스를 개발하는 개발자.**

루티 API를 사용하는 개발자들은 루티의 기능을 자신의 서비스에 자유롭게 활용함으로써, 루티의 가치를 외부에 확장하고, 궁극적으로 더 많은 사용자들이 루티의 데이터를 생산하도록 기여하게 됩니다.

### 3. 동선 검증 API 를 공개해야 하는 이유

**💡 루티의 핵심인 동선 검증 기능을 다양한 클라이언트에게 제공하기 위해.**

**“익숙함에 가려진 불편을 해결하는 것”** 은 저희 서비스가 추구하는 핵심 가치입니다.

여행 동선의 실현 가능성을 검증하는 과정은 여러 API와 복잡한 로직을 구현해야 하는 번거로운 작업입니다. 동시에, 요구사항을 받고 코드를 작성하고 어떻게 구현해야 할지 고민하는 과정은 개발자에게 익숙한
상황입니다.

루티의 동선 검증 기능을 Open API로 제공함으로써, 각자의 서비스에서 새로운 가치를 창출할 수 있도록 도울 수 있습니다. 이는 루티 팀이 추구하는 핵심 가치를 실현하는 효과적인 방법입니.

**💡 루티 외부의 개발자들이 루티를 위해 함께 일하게 만드는 것.**

저희는 가치 있는 데이터를 생산하는 사용자를 확보하기 위해 노력하고 있습니다. 만약, 루티의 동선 검증 기능이 Open API로 공개된다면 어떨까요?

다른 서비스들이 루티 API를 활용해 새로운 가치를 창출하는 동시에, 루티의 동선 검증 데이터를 자연스럽게 생산하게 될 것입니다. 저희가 직접 일하지 않아도 루티의 데이터 생태계가 확장되는 것입니다.

저희는 루티 안팎에서 생산된 모든 데이터를 분석하여, 루티를 더욱 풍부하고 가치 있는 서비스로 발전시킬 수 있습니다.

# 데이터 분석

DB 데이터를 제공하지 않음.

장소 이름에 해당하는 위/경도, 지번 주소, 도로명 주소 데이터 존재. (실제로 데이터는 존재하지 않지만, 루티 서비스 내에서 외부 API 를 통해 정보를 가져올 수 있음).

# 페르소나 도출

**역할**: 여행 서비스를 개발하고 있는 백엔드 개발자.

**경력**: 웹 개발, 데이터 분석 경력 5년

**기술 수준**:

1. REST API 설계·호출 경험 보유 (HTTP 메서드, 엔드포인트 구조 이해)
2. Postman, curl 활용 테스트 가능
3. 목표: 사용자가 정한 동선을 여행할 수 있는 지 검증 후, 여행할 수 없다면 최적의 동선을 추천해주는 기능 개발.

# 요구사항 도출

사용자가 정한 동선을 여행할 수 있는 지 검증 후, 여행할 수 없다면 최적의 동선을 추천해주는 기능을 개발해야 함.

사용자가 정한 동선을 여행할 수 있는 지 검증하는 기능을 구현하기엔 너무 복잡하고, 장소명에 따른 위/경도 데이터가 없어 외부 API 를 사용하려고 함.

장소 이름들, 여행 시작/종료 시간을 통해 실현 가능한 동선인지 판단하는 API 가 필요함.

# API 설계 (V0.0.0)

## Request

### Body

**Root**

| 키                | 필수 여부 | 타입             | 설명                         |
|------------------|-------|----------------|----------------------------|
| `places`         | O     | `Array<Place>` | 장소 배열                      |
| `startAt`        | O     | `Date`         | 여행 시작 일시(yyyy-MM-ddTHH:mm) |
| `endAt`          | O     | `Date`         | 여행 종료 일시(yyyy-MM-ddTHH:mm) |
| `movingStrategy` | O     | `String`       | 이동 수단                      |

**Place**

| 키           | 필수 여부 | 타입        | 설명    |
|-------------|-------|-----------|-------|
| `sequence`  | O     | `Integer` | 장소 순서 |
| `latitude`  | O     | `Double`  | 위도    |
| `longitude` | O     | `Double`  | 경도    |

## Response

### Body

**ValidationResults**

| 키                                    | 필수 여부 | 타입                     | 설명               |
|--------------------------------------|-------|------------------------|------------------|
| `validationResults`                  | O     | `Array<Object>`        | 검증 결과 객체 배열      |
| `validationResults[].validationCode` | O     | `String`               | 검증 코드            |
| `validationResults[].isValid`        | O     | `Boolean`              | 유효 여부            |
| `validationResults[].invalidPlaces`  | O     | `Array<InvalidPlaces>` | 유효하지 않은 장소 객체 배열 |

**InvalidPlaces**

| 키                          | 필수 여부 | 타입        | 설명                  |
|----------------------------|-------|-----------|---------------------|
| `invalidPlaces[].sequence` | O     | `Integer` | 유효하지 않은 장소 sequence |

```json
{
  "validationResults": [
    {
      "code": "IS_WITHIN_TOTAL_TIME",
      "isValid": true,
      "invalidPlaceSequences": []
    }
  ]
}
```
